# Geowinch

Проект Geowinch — ПО панели управления (HMI) геофизической лебёдки. Исходная база — WinchCtrl v5.0.0 (клон test5), сборка RAD Studio 12 (C++ Builder). Обмен с контроллером Bosch Rexroth RC12-10/30 (BODAS 3.0) по CAN 250 kbit/s, ID 0x101–0x305.

### ⚠️ ВАЖНО про библиотеки (DLL)

Программа **не запустится / не инициализирует CAN без DLL рядом с exe**:

| DLL | Зачем | Когда нужна |
|-----|-------|-------------|
| `PCANBasic.dll` | CAN-обмен через PEAK (PCAN-USB) | всегда (настоящая, 1 787 624 байт) |
| `PCANBasicSim.dll` | **Эмулятор** CAN для проверки без адаптера | только для теста (подменяется, ~52 КБ) |
| `Adsapi32.dll` | Обмен с TwinCAT/ADS (Beckhoff) | если используется ADS |
| `Adsapi32_20031230.dll` | Резервная версия ADS | если используется ADS |

> Программа грузит `PCANBasic.dll` **динамически** (LoadLibrary), поэтому работает подмена файла: что лежит рядом с exe под именем `PCANBasic.dll` — то и используется.

## 1. Установка на панель (Windows 10 x64 / Windows 10 IoT Enterprise) — чек-лист

1. **Установить PEAK-Drivers 5.1.2** — один раз, от администратора (инсталлятор в поставке; тихая команда: `PeakOemDrv.exe /exenoui /qn ADDLOCAL=F_DRIVERS,F_PCANBASIC`). Проверка: Диспетчер устройств → **CAN-Hardware** → **PCAN-USB**. Подходят также версии 4.4+ (старые 3.x не ставить).
2. **Скопировать папку программы** — распаковать zip из релиза (**5 файлов**: exe + `PCANBasic.dll` + `PCANBasicSim.dll` + 2×Adsapi32) в одну папку, например `C:\WinchCtrl`.
3. **Воткнуть PCAN-USB и соединить шину** — CAN_H/CAN_L к контроллеру RC12-10/30, скорость **250 kbit/s**, терминатор **120 Ом** на концах шины.
4. **Запустить exe** — всё. Канал `PCAN_USBBUS1` (0x51) и скорость 250 kbit/s зашиты в код, настраивать ничего не нужно.

### Нюансы

- **`PCANBasic.dll` в папке должна быть настоящей** (1 787 624 байт) — в zip она по умолчанию настоящая, эмулятор лежит отдельно под именем `PCANBasicSim.dll`. Эмулятор подменяют **только для проверки без адаптера** (раздел 3) и потом возвращают обратно.
- **Адаптер должен быть настоящим PCAN-USB** (или официально совместимым) — дешёвые клоны с драйвером PEAK не работают.
- **PCAN-View не нужен для работы** — это только диагностика (проверить, что кадры ходят). Программа общается с адаптером сама.

Итог на объекте: драйвер поставили → папку скопировали → адаптер воткнули → работает. Если адаптер не был подключён при запуске — программа сама подхватит его в течение секунды (ретрай каждые 1000 мс).

## 2. Как проверить отправку 0x101 — с железом (PCAN-USB)

1. PCAN-USB подключён, драйвер PEAK установлен (шаг 1 выше).
2. Запустить PCAN-View → канал `PCAN_USBBUS1`, скорость **250 kbit/s**.
3. Запустить программу, нажать и **удерживать «Сирена»** (кнопка слева внизу).
4. В PCAN-View видно `101` каждые ~500 мс: `57 43 <main> <mid> <rev> 00 00 00` (= «W C» + версия). Контроллер в ответ шлёт `201` (`57 43 53 ...`).

Программа и без нажатий постоянно передаёт: `101` (~каждые 520 мс), `102` (статус, ~80 мс), `103`, `104`. При удержании «Сирены»: `101` идёт **парами** (доп. отправка каждые ~500 мс) и первый байт `102` меняется `22 → A2` (бит 7 = «сирена активна»).

## 3. Как проверить отправку 0x101 — БЕЗ железа (эмулятор PCANBasicSim.dll)

Никакой CAN-адаптер и даже драйвер PEAK **не нужны** — программа не отличает эмулятор от реального устройства.

### Подмена DLL (проверка потока)

1. В папке программы **переименовать** настоящую библиотеку в бэкап:
   ```
   PCANBasic.dll  →  PCANBasic.dll.real
   ```
2. **Скопировать эмулятор** под рабочим именем:
   ```
   PCANBasicSim.dll  →  PCANBasic.dll
   ```
3. Запустить `WinchCtrl_TEST_v0.0.3.exe`.
4. Рядом с программой откроется **чёрное окно консоли** — живой поток кадров, которые программа «отправляет в шину», в реальном времени.
5. Нажать и удерживать **«Сирена»** — в консоли появятся дополнительные `TX 0x00000101` каждые ~500 мс.
6. Тот же поток пишется в файл **`pcan_shim.log`** рядом с exe (открывается Блокнотом):
   ```
   [16.08.2026 16:53:12.829] CAN_Initialize: канал 0x51, baud=0x011C (симуляция) -> OK
   [16.08.2026 16:53:12.881] TX 0x00000101 STD 8: 57 43 05 00 00 00 00 00
   [16.08.2026 16:53:13.429] TX 0x00000102 STD 8: 22 00 00 00 00 00 27 10
   ```
   Формат строки: `[дата время.мс] TX/RX <ID> <STD/EXT> <длина>: <байты>`.

### Возврат к реальной работе

1. Закрыть программу.
2. Удалить эмулятор и вернуть настоящую библиотеку:
   ```
   del PCANBasic.dll
   ren PCANBasic.dll.real PCANBasic.dll
   ```
3. Проверить, что размер `PCANBasic.dll` = **1 787 624 байт** (эмулятор ~52 КБ — если меньше, работать с железом не будет).

### Как эмулятор отвечает программе

- `CAN_Initialize` → «успех» (программа считает, что адаптер есть);
- `CAN_Write` → кадр записывается в лог/консоль, «успех»;
- `CAN_Read` → «очередь пуста» (как пустая шина);
- эмуляция ответа контроллера (например `201`): создать рядом с exe файл `pcan_inject.txt` со строкой:
  ```
  0x201,8,87,67,83,32,49,46,48,32
  ```
  — при следующем опросе шим отдаст этот кадр как «принятый» (в логе строка `RX 0x00000201 ...`).

### Примечания

- Эмулятор **нельзя использовать на реальном объекте** — он ничего не отправляет в шину, только имитирует.
- Консоль можно отключить: создать пустой файл `pcan_shim_noconsole.txt` рядом с exe (лог в файл продолжит писаться).
- PCAN-Virtual от PEAK для этой проверки **не подходит**: по официальной позиции PEAK-System, PCAN-Basic API работает только с реальным железом (виртуальный драйвер — только для API PCAN-Developer).

## Правки относительно v5.0.0 (суммарно)

1. `WCAnalysis.h` — таймер `ActSignalHorn_101_Time_old`.
2. `WCAnalysis.cpp` — `ActSignalHorn()`: кнопка «Сирена» шлёт CAN 0x101 (`W C + версия`) каждые 500 мс при удержании.
3. `WCAnalysis.cpp` — `ActCtlUnitCAN_O()`: снята блокировка `StatusLvl != Ready → return`.
4. `GUIMain.cpp` — `FormShow()`: надпись «ТЕСТОВАЯ ВЕРСИЯ v0.0.3» (чёрная, жирная) + кнопка «Выход» над «Ручное управление».
5. **Юникод-фикс (кракозябры на панели с ACP≠1251)**: `Labelling.h` — 217 массивов надписей `const char*` → `const wchar_t*` (`L""`); `GUIMain.cpp` — касты `(AnsiString)` → `(UnicodeString)` (5 мест); `WCLog.cpp` — `strlen` → `wcslen` (28 мест, заголовки логов GEOSYS). Статичные надписи DFM-форм пересохраняются в RAD Studio (см. `docs/План_документации_изделия.md`). Альтернатива без пересборки — `tools/set_ACP_1251.reg` (системная локаль панели → русская).
